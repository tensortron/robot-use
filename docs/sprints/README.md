# Sprint plans

One file per sprint: `YYYY-MM-DD-<topic>.md`. Written before the work, approved by the user, then kept up to
date as the work log of that sprint (see AGENTS.md, "How work is done"). Lasting results are consolidated into
the design docs (AGENTS.md, "How work is done", step 5).

## Template

```markdown
# Sprint YYYY-MM-DD: <topic>

Status: draft | approved YYYY-MM-DD | in progress | done YYYY-MM-DD

## Context
Why this sprint; what was found that led to it; what state things are in (including uncommitted work).

## Goal
What is true when it is done.

## Decisions needed
| # | question | options | recommendation | decision |

## Tasks
| # | task | depends on | acceptance | status |

## Risks and safety
Hardware steps, who must be present, what could go wrong and how it fails.

## Work log
Dated entries: what was done, found, reviewed (findings and how handled), test results, commits (approved by
the user), what is left.
```
